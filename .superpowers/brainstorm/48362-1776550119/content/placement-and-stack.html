Placement and tech stack

Two quick decisions that are tightly coupled. Default strong recommendation highlighted.

URL placement

A

New path: /dominion-admin/ (recommended)

Keeps /dominion-demo/ as the engineering walkthrough (proves the data pipeline works). New page is the Dominion-facing admin dashboard. Same FastAPI service, new static files.

B

Replace /dominion-demo/

Admin dashboard becomes THE Dominion-facing demo. Engineering panels live in a hidden /dominion-demo/engineering/ route for debugging.

Frontend tech

A

Vanilla JS + Chart.js + Leaflet (recommended)

Consistent with existing /dominion-demo/. No build step, no tooling. Add Alpine.js (lightweight, CDN) for the reactivity the dashboard needs. Same deploy path.

B

Vue 3 (CDN, no build)

Better for the many repeating components (zone cards, device rows, event rows). Matches WattCarbon main stack. Still no build step. Small cognitive jump from the current JS style.

C

React via CDN

Preact/React with htm for a no-build workflow. Most familiar component model. Adds ~10 KB vs A.
